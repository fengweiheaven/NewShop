# 序单 OrderFlow

面向商贸代发业务的浏览器订单工作台。把不同客户提供的订单表格，转换成可核对的统一订单，再按供应商拆分、导出各自需要的列结构。

本版本是纯前端网页，无需构建、安装依赖或配置后端服务。

## 四个功能模块

| 模块 | 功能 |
| --- | --- |
| 商品映射库 | 维护供应商、标准商品、规格、内部编码、供应商编码及客户商品别名，建立商品与供货方的对应关系。 |
| 订单采集与匹配 | 批量导入不同格式的客户订单，选择工作表和表头行，调整字段对应关系，在映射库中查找商品与供应商，并处理待确认项。 |
| 统一订单 | 将选定批次整理为统一明细，保留客户、商品、数量、供应商及原文件、工作表、行号等来源信息，核对后下载 Excel。 |
| 供应商模板 | 按供应商拆分统一订单，配置输出列名、取值来源、默认值及必填项，生成各供应商的 Excel 订单文件。 |

## 运行方式

### 使用静态服务器

在项目根目录运行：

```bash
python -m http.server 8765 --directory dist
```

然后在浏览器中打开 [http://localhost:8765](http://localhost:8765)。Python 仅用于提供静态文件，订单处理逻辑仍在浏览器中运行。

### 使用单文件 HTML

下载 [standalone/OrderFlow.html](standalone/OrderFlow.html)，保存到本机后用现代浏览器打开。该版本将页面、样式和脚本合并为一个文件，不需要启动静态服务器。

直接打开 HTML 文件时，本地存储可用性取决于浏览器及其文件访问设置。需要稳定保存工作区时，建议使用上面的静态服务器方式。

## 首次使用

1. 在“商品映射库”核对供应商资料、商品编码与规格，并补充客户商品别名。
2. 在“订单采集与匹配”上传当天的订单，核对客户名称、工作表、表头行和字段映射。
3. 检查未匹配商品、歧义、重复记录及缺少必填字段的行。确认商品与供应商对应关系后，再生成统一订单。
4. 在“统一订单”检查需要交付的明细，下载统一格式文件。
5. 在“供应商模板”核对供应商输出列及必填规则，按供应商拆分导出。

已预置“友本”供应商的 **11 个商品 SKU** 和 **7 列订单模板**：订单号、买家昵称、收货人、详细地址、收货人电话、商品编码、数量。供应商名称取自样表；实际供应商主体信息、供货关系和候选商品映射仍需业务人员核对确认。

## 文件格式与模板边界

- 订单、商品资料和模板入口支持标准 `.xlsx` 与 UTF-8 `.csv`。旧版 `.xls` 请先另存为 `.xlsx`。
- 单个文件不超过 15 MB；复杂、加密或损坏的工作簿需要先在 Excel 中整理后再导入。
- 可选择工作表、表头行并手动调整字段。建议让每行对应一条订单商品明细，保留清晰的订单号、商品名称、规格和数量。
- 供应商模板功能保存的是**列结构与取值规则**。导出会生成新的 Excel 文件，保留所配置的列名和顺序；不会复刻原模板的合并单元格、说明区、完整样式、公式或其他原始版式。
- 当前范围为上述四个模块；微信群自动抓单、供应商后台自动提交、物流回单和财务对账不在本版本范围内。

## 数据保存与备份

商品库、映射规则和工作区订单使用浏览器本地 IndexedDB 保存。当前没有业务后端、账号体系、云端数据库或跨设备同步；导入文件的解析与导出在浏览器中完成。

不同浏览器、浏览器配置文件、访问地址及单文件版本可能使用不同的本地存储空间。清理浏览器数据也可能清除工作区。可使用右上角“备份数据”导出 JSON，在需要时通过“恢复备份”导入。备份包含业务数据，应由使用者自行保管，不提交到源代码仓库。
